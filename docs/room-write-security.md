# 직접 방 수정·삭제 경로 제한

## 범위

이 변경은 `rooms` 테이블의 직접 UPDATE/DELETE에서 `owner_user_id IS NULL`이 누구나 수정 가능한 조건으로 작동하던 경로를 제한합니다. 기존 permissive 정책은 보존하고 restrictive 정책을 추가해 우회되지 않도록 합니다.

- 로그인한 소유자는 자기 방을 직접 수정·삭제할 수 있습니다.
- 익명 요청이나 다른 로그인 사용자는 해당 방을 직접 수정·삭제할 수 없습니다.
- 익명 방장의 동작은 참여 토큰을 검사하는 Edge Function 경로로 처리해야 합니다. 서비스 역할을 사용하는 함수는 RLS를 우회하므로 함수 내부 인증·인가가 반드시 필요합니다.

현재 클라이언트의 일정·장소 확정은 Edge Function을 호출합니다. 이 PR은 함수 권한 검사까지 완전히 검증하거나 새 익명 소유권 모델을 도입하지 않습니다. 직접 DB 수정에 의존하던 다른 화면이 있다면 적용 전에 확인해야 합니다.

## 검증

격리된 PostgreSQL 16에서 기존 방 정책과 같은 조건을 재현하고, 새 마이그레이션을 적용한 뒤 허용·거부 9개를 확인하는 CI를 추가했습니다. Supabase Auth 대신 테스트용 `auth.uid()`를 사용하므로 실제 Supabase JWT 검증·Edge 배포 검증은 아닙니다.

운영 DB에 마이그레이션을 자동 적용하지 않습니다. 적용 전 실제 정책 목록과 배포된 함수의 인증·인가를 확인하세요. 참여자·비용·투표 정책, RPC 컨텍스트 수명, 소유자 없는 기존 데이터의 소유권 복원은 이 제한된 수정의 범위 밖입니다.
